## 1. Branching Strategy

### 1.1 Branch Naming Convention

```
<type>/<phase>-<short-description>

Types:
  feat     = New feature
  fix      = Bug fix
  refactor = Code restructure
  test     = Tests only
  docs     = Documentation
  chore    = Build, CI, deps
  hotfix   = Emergency production fix
```

**Examples:**
```
feat/p20-kill-switch
fix/p20-argparse-duplicate
test/p20-telemetry-writer
docs/p21-runbook-update
hotfix/critical-api-crash
```

### 1.2 Branch Hierarchy

```
main (protected)
├── develop (integration)
│   ├── feat/p20-kill-switch
│   ├── feat/p20-telemetry-writer
│   └── test/p20-unit-tests
└── hotfix/critical-fix (direct to main)
```

### 1.3 Branch Rules

| Rule | Requirement |
|------|-------------|
| Main protection | No direct commits, PR required |
| Develop protection | Sanity check must pass |
| Feature branches | Must branch from develop |
| Hotfixes | May branch from main |
| Stale branches | Delete after 14 days |

## 2. Pre-Commit Checklist

Before every commit, the agent/developer MUST verify:

```markdown
## Pre-Commit Checklist

### Hygiene
- [ ] `./Scripts/repo_sanity_check.sh` passes
- [ ] No .rej or .orig files
- [ ] No __pycache__ or .pyc files
- [ ] No secrets in code

### Code
- [ ] Code follows existing patterns
- [ ] Type hints on public functions
- [ ] No debug print statements
- [ ] No TODO without issue reference

### Tests
- [ ] Relevant tests pass: `pytest tests/unit/ -v`
- [ ] No test regressions
- [ ] New code has tests

### Commit Message
- [ ] Follows format: `type(scope): description`
- [ ] References task ID if applicable
- [ ] Under 72 characters for title
```

## 3. Pre-Merge Checklist

Before merging ANY branch:

```markdown
## Pre-Merge Checklist

### Sanity
- [ ] `./Scripts/repo_sanity_check.sh` passes on branch
- [ ] `git status` shows clean working tree
- [ ] No merge conflicts

### Quality
- [ ] All unit tests pass: `pytest tests/unit/ -v`
- [ ] All integration tests pass: `pytest tests/integration/ -v`
- [ ] Code review complete (human or AI)

### Documentation
- [ ] README updated if needed
- [ ] Docs/STATUS.md reflects changes
- [ ] CHANGELOG.md entry added
- [ ] Agent Work Log complete

### Verification
- [ ] Paper daemon starts without error
- [ ] Heartbeat updates correctly
- [ ] No new warnings in logs

### Final
- [ ] Branch rebased on target (no merge commits)
- [ ] Commit history is clean
- [ ] PR description explains changes
```

## 4. Commit Message Format

```
<type>(<scope>): <short description>

[optional body - wrap at 72 chars]

[optional footer - refs, breaking changes]
```

### Types

| Type | Use For |
|------|---------|
| `feat` | New feature |
| `fix` | Bug fix |
| `refactor` | Code restructure (no behavior change) |
| `test` | Adding/updating tests |
| `docs` | Documentation only |
| `chore` | Build, deps, CI |
| `perf` | Performance improvement |

### Examples

```
feat(risk): implement 3-level kill-switch

- Add RiskLevel enum with NORMAL/SOFT/HARD/HALT
- Implement trigger evaluation
- Add recovery logic

Refs: P20-001

---

fix(daemon): resolve duplicate argparse flag

The --max_exp_move_bps flag was defined twice, causing crash loops.

Fixes: #123
```

## 5. Never Commit List

These files/patterns MUST NEVER be committed:

| Pattern | Reason |
|---------|--------|
| `runs/` | Session artifacts, large |
| `logs/` | Runtime logs |
| `*.csv` | Data files (except whitelisted) |
| `*.parquet` | Binary data |
| `__pycache__/` | Generated bytecode |
| `*.pyc` | Compiled Python |
| `*.rej` | Patch failures |
| `*.orig` | Merge leftovers |
| `.env*` | Secrets |
| `*.log` | Log files |
| `venv/` | Virtual environment |

If accidentally committed:
```bash
git rm --cached <file>
git commit -m "chore: remove accidentally committed artifact"
```

## 6. Hotfix Protocol

For critical production issues:

```bash
# 1. Branch from main
git checkout main
git pull origin main
git checkout -b hotfix/critical-description

# 2. Fix the issue
# ... make changes ...

# 3. Test thoroughly
pytest tests/unit/ -v
./Scripts/repo_sanity_check.sh

# 4. Commit with urgency marker
git commit -m "hotfix(scope): URGENT fix description

- What was broken
- What this fixes
- How to verify"

# 5. Merge to main (fast-track review)
git checkout main
git merge hotfix/critical-description

# 6. Tag the hotfix
git tag -a v0.X.Y-hotfix -m "Hotfix: description"

# 7. Also merge to develop
git checkout develop
git merge hotfix/critical-description

# 8. Delete hotfix branch
git branch -d hotfix/critical-description
```

## 7. Emergency Rollback

If a merge breaks production:

```bash
# Option 1: Revert last merge
git revert -m 1 <merge-commit-hash>
git push origin main

# Option 2: Reset to known good state
git checkout main
git reset --hard <known-good-commit>
git push --force-with-lease origin main

# Option 3: Deploy previous tag
git checkout v0.X.Y-previous
./Scripts/phase19ctl.sh restart
```

**Always notify the team immediately when rolling back.**
